# UI/UX Sweep — 2026-08-07

Method: live walkthrough of the hosted demo (light + dark theme, EN + DE, desktop + 390px mobile) cross-checked against the frontend source. Findings are ordered by priority; each has a file reference where a code change applies.

## High

### H1. Destructive actions without confirmation
The row trash icon on a test case and the delete button on a user dispatch immediately — no confirm dialog, no undo:

- `test-case-list.component.ts:403` — `deleteTestCase()` dispatches directly
- `user-list.component.ts:74` — `deleteUser()` dispatches directly

Folder delete and bulk delete on the same screen *do* open `ConfirmDialogComponent`, so the pattern exists; these two just skip it. The user list also renders a delete button for the signed-in admin's own account with no client-side guard (self-delete / last-admin).

**Fix:** route both through `ConfirmDialogComponent` with `danger: true`; disable delete on the current user's row.

### H2. Global search (Cmd-K) never shows server results
Searching "test" in the demo returns "No matches in what's already loaded" even though Test1/Test2/ReleaseRun2 exist and `/api/search` is implemented. Probable cause: the app is zoneless (`provideZonelessChangeDetection()`, `app.config.ts:45`), and `serverFallback()` in `command-palette.component.ts:178-203` mutates `this.results.push(...)` inside an RxJS subscribe — nothing schedules change detection, so appended server hits never render. Local matches work only because keystroke events trigger CD.

Also: while the debounced server call is in flight, the empty state already claims "no matches" (no loading indicator), and a failed request is silently swallowed.

**Fix:** make `results` a signal (or call `ChangeDetectorRef.markForCheck`), add a pending state, surface errors.

### H3. Project dashboard is full-bleed (no page padding)
Cards touch the sidebar and viewport edge and get clipped, desktop and mobile. Cause: every list page defines its own `.list-container`; `project-dashboard.component.scss` uses the class in its template but never defines it. The copies that exist have drifted (24px vs 32px padding, 1200px vs 1400px max-width) across 8 components.

**Fix:** define `.list-container` once in `styles.scss` (like `.page-header`, `.tm-card`) and delete the per-component copies.

## Medium

### M1. Red-seeded Material theme tints every surface pink
`styles.scss:105-120` seeds M3 themes with `mat.$red-palette` as primary, so Material-derived surfaces (form cards, dialogs, menus, paginator footers, expanded rows, hover/selected states) render rose-tinted while `--tm-*` cards stay neutral white. Visible everywhere: the entire Create Test Case form is pink, a **passed** result row has a pink background (reads as failure), theme/language menus are pink, table footers are pink. Tinted surfaces conflict with red = danger/accent semantics used elsewhere.

**Fix:** override the M3 neutral/surface tokens (or use a neutral seed for surfaces) so only intentional accents are red.

### M2. "ACTUAL RESULTokay" — label and value run together
Read-only step results render two inline spans with no separator: `test-run-detail.component.html:356-357`; `.step-actual-readonly` (`.scss:235`) sets only `margin-bottom`. Displays as `ACTUAL RESULTokay`.

**Fix:** stack or gap the spans, matching `app-step-spec-card`'s label/value layout.

### M3. Icon-only buttons missing accessible names
`user-list.component.html` does it right (`[attr.aria-label]="'Delete ' + user.email"`), but the pattern isn't applied elsewhere: test-case row edit/delete, folder menu / create-folder / bulk-deselect (`test-case-list.component.html:48,61,97,272`), run-list actions, run-detail bookmark. The spacer `<button mat-icon-button disabled><mat-icon></mat-icon></button>` (`:89`) is an empty focusable control — use a CSS spacer instead.

### M4. Tables don't adapt to small screens
At 390px the test case table overflows and drags a page-level horizontal scrollbar; the header wraps with "Create Test Case" overlapping Import/Export. Minimum: wrap tables in an `overflow-x` container and let the header stack; better: collapse rows to cards on narrow viewports.

### M5. Run detail toolbar overload
Six same-weight outlined controls (bookmark icon, Reopen, Report, Upload Allure Report, Clone, Delete). Delete sits directly beside Clone at equal prominence. "Upload Allure Report" is jargon if Allure isn't configured. Suggest: keep Report + primary state action visible, move Clone/Upload/Delete into an overflow menu with Delete separated.

### M6. Hardcoded version "v0.1.0"
`shell.component.html:27` — hardcoded while the product is v2.x. Misleading in every screenshot. Wire to the build version (e.g., import from `package.json` or an env stamp at build time).

## Low

- **L1. Terminology drift:** form tab "Script" (`tabScript`) vs "Test Steps" everywhere else. Button casing mixes title and sentence case ("Create Test Case", "Add Member" vs "Add requirement"). "Trace requirements to tests and see coverage" is missing its period (the other seven cards have one).
- **L2. Back-link inconsistency:** red and cramped above the title on the project dashboard, grey and inline on every other page.
- **L3. "1 / 0 / 1" recent-run results:** unexplained colored counts; the failed count renders red `#f44336` (hardcoded, `project-dashboard.component.scss:72`) even when it's 0. Use `--tm-danger`, mute zero values, add a tooltip/legend.
- **L4. Token bypasses:** 65 hardcoded hex colors across 21 component SCSS files (19 in `test-run-detail.component.scss` alone) — erodes the PRD-013 `--tm-*` theming contract. Worth a cleanup pass.
- **L5. Language menu** doesn't mark the active language; the theme menu shows a checkmark. Same menu, different affordance.
- **L6. Admin role chip** uses the danger tint — admin reads as a warning. Neutral or brand tint fits better.
- **L7. Pass Rate Trend with one run** renders a single dot pinned to the top-left of an empty chart. Below ~3 points, show "Not enough runs yet to draw a trend."
- **L8. Duplicate `.form-container`:** global (`styles.scss:303`, 640px/24px) vs `test-case-form.component.scss:1` (800px/32px).
